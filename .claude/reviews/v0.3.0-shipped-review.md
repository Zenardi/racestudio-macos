# Code Review: everything shipped in v0.2.3 → v0.3.0

**Reviewed**: 2026-09-27
**Scope**: the four stages — library management, track database, map imagery, lap
scrubber. 29 source files, +2170 / −194.
**Decision**: APPROVE (one MEDIUM finding fixed; no CRITICAL or HIGH)

## Summary

A full pass over the work shipped as v0.2.3–v0.3.0, which predates the standing
review step. No security issues and no correctness defects found. One real
performance defect (an O(n log n) lookup where O(1) was available) is fixed. The
adversarial checks on the file-writing and file-deleting paths all held.

## Findings

### CRITICAL
None.

### HIGH
None.

### MEDIUM
1. **Resolving one session by id sorted the whole library** — FIXED.
   `SessionIndex.summaries` calls `byDateDescending` over every value on *each*
   access. Three call sites used it to fetch a single row — `selectedSummary`
   (pre-existing, and evaluated on every render of the browser's preview pane),
   plus `canDiscardCopy` and `delete` added in this work. `storage` is already a
   dictionary keyed by that exact id, so `SessionIndex.summary(id:)` now answers in
   O(1) and all three use it.

### LOW
2. **`ManagedFileStore.adopt` rescans the directory on a digest miss.** Only when the
   preferred name is absent *and* the content might exist under another name, so at
   most one `contentsOfDirectory` per genuinely new import. Correct as written; noted
   because a very large managed directory would make it linear.
3. **`AppModel.importToLibrary` saves the whole index once per imported file.** A
   10-file drag writes `library.json` ten times. Harmless at realistic sizes and
   deliberately best-effort (a failed save is non-fatal), but a single save after the
   loop would be strictly better.

## Adversarial checks that held

| Check | Result |
|---|---|
| Path traversal via `ManagedFileStore.managedName` | Safe. `/`, `\`, `:` are replaced and `..` collapsed; input is a `lastPathComponent` anyway. Covered by a test using `../../etc/passwd`. |
| Deleting outside the managed directory | Safe. `discard` compares the *parent* against the managed directory after `standardizedFileURL`, so `..` segments and sibling directories are rejected; a symlinked entry deletes the link, not its target. |
| `Int(Double)` traps (the class fixed in `LapTimeFormatter`/`TimecodeFormatter`) | Swept all of Core. Every other site is bounded before conversion — `Histogram` guards `span <= maxBins`, `SectorModel` clamps by `lapDistance`, `ChannelColorScale` guards NaN and maps through a clamped scale, `ChannelStatistics` clamps the percentile, `TickGenerator`'s step scales with the span. The two formatters were genuine outliers, not a pattern. |
| Force unwraps / `try!` in shipped Core | None. |
| Concurrent `adopt` of the same content | Safe. Same digest → same path → atomic write of identical bytes. |
